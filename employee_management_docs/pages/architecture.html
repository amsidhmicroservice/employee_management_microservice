Sequence Flow Diagrams

Employee Creation Flow

100%

Process Steps:

  1. Request Validation: API Gateway validates incoming request format and authentication
  2. Lambda Trigger: Create Employee Lambda function is invoked
  3. Data Validation: Employee data is validated against business rules
  4. Database Write: Employee record is stored in DynamoDB
  5. Response: Success confirmation with employee ID returned to client

Employee Get by ID Flow

100%

Process Steps:

  1. Authentication: Request authentication and authorization check
  2. Lambda Execution: Get Employee Lambda function processes request
  3. ID Validation: Employee ID format validation and existence check
  4. Database Query: Employee data retrieved from DynamoDB by primary key
  5. Response Formatting: Raw data transformed to API response format
  6. Response Delivery: Employee data returned to requesting client

Employee Get All Flow

100%

Process Steps:

  1. Authentication: Request authentication and role-based authorization
  2. Parameter Parsing: Extract pagination, filtering, and sorting parameters
  3. Database Scan: Perform optimized scan/query on DynamoDB table
  4. Pagination: Apply limit and offset for efficient data retrieval
  5. Data Formatting: Transform and format employee list for API response
  6. Response Delivery: Return paginated employee list with metadata

Employee Update Flow

100%

Process Steps:

  1. Request Validation: Validate update data and authorization check
  2. Employee Existence Check: Verify employee exists before update operation
  3. Data Merging: Merge new data with existing employee record
  4. Atomic Update: Perform conditional update operation in DynamoDB
  5. Audit Logging: Record change history for compliance and tracking
  6. Response Confirmation: Return updated employee data to client

Employee Delete Flow

100%

Process Steps:

  1. Admin Authorization: Verify admin-level permissions for delete operation
  2. Employee Existence Check: Confirm employee exists before deletion
  3. Audit Trail Creation: Log deletion event with timestamp and user info
  4. Soft Delete Operation: Mark employee as deleted instead of physical removal
  5. Related Data Update: Update references and maintain data integrity
  6. Deletion Confirmation: Return success confirmation to requesting client
