Update Employee Flow 

sequenceDiagram
    participant C as 👤 Client
    participant AG as 🌐 API Gateway
    participant L as ⚡ Lambda Function
    participant V as ✅ Validator
    participant DB as 🗄️ DynamoDB
    
    Note over C,DB: ✏️ PUT /employees/{id} - Update Employee
    
    C->>+AG: 📤 PUT /employees/{employee_id}
    Note right of C: 🔑 x-api-key: {api-key}
📋 Content-Type: application/json
📦 Body: updated fields
    
    AG->>AG: 🔐 Validate API Key
    AG->>AG: 🚦 Check Rate Limits
    
    alt ❌ API Key Invalid
        AG-->>C: 🚫 401 Unauthorized
    else ✅ Valid Request
        AG->>+L: ➡️ Forward Request
        L->>L: 🔍 Extract Employee ID
        L->>L: 📖 Parse Request Body
        
        L->>+DB: 👀 Check Employee Exists
        
        alt ❌ Employee Not Found
            DB-->>L: 🚫 Item Not Found
            L-->>AG: 🔍 404 Not Found
            AG-->>C: ❌ 404 Not Found
        else ✅ Employee Found
            DB-->>-L: 📋 Current Employee Data
            
            L->>+V: ✔️ Validate Update Data
            
            alt ❌ Validation Failed
                V-->>L: ⚠️ Validation Errors
                L-->>AG: 🚫 400 Bad Request
                AG-->>C: ❌ 400 Bad Request
            else ✅ Validation Passed
                V-->>-L: ✅ Validation Success
                
                L->>L: 🔧 Build Update Expression
                L->>+DB: 💾 Update Employee Record
                
                alt ❌ Update Failed
                    DB-->>L: 💥 Update Error
                    L-->>AG: 🚫 500 Internal Server Error
                    AG-->>C: ❌ 500 Internal Server Error
                else ✅ Update Success
                    DB-->>-L: 📋 Updated Employee Data
                    L->>L: 🎨 Format Response
                    L-->>-AG: ✅ 200 OK
                    AG-->>-C: 🎉 Updated Employee
                end
            end
        end
    end

✏️ Update Employee Process

👀 Existence Verification

Verify employee exists before attempting update operation with comprehensive existence checking

✔️ Partial Validation

Validate only the fields being updated, supporting partial updates with flexible validation rules

💾 Atomic Update

Perform atomic update operation with automatic timestamp management and data integrity

Delete Employee Flow 

sequenceDiagram
    participant C as 👤 Client
    participant AG as 🌐 API Gateway
    participant L as ⚡ Lambda Function
    participant DB as 🗄️ DynamoDB
    
    Note over C,DB: 🗑️ DELETE /employees/{id} - Delete Employee
    
    C->>+AG: 📤 DELETE /employees/{employee_id}
    Note right of C: 🔑 x-api-key: {api-key}
🆔 employee_id in path
    
    AG->>AG: 🔐 Validate API Key
    AG->>AG: 🚦 Check Rate Limits
    
    alt ❌ API Key Invalid
        AG-->>C: 🚫 401 Unauthorized
    else ✅ Valid Request
        AG->>+L: ➡️ Forward Request
        L->>L: 🔍 Extract Employee ID
        
        L->>+DB: 👀 Check Employee Exists
        
        alt ❌ Employee Not Found
            DB-->>L: 🚫 Item Not Found
            L-->>AG: 🔍 404 Not Found
            AG-->>C: ❌ 404 Not Found
        else ⚠️ Employee Already Deleted
            DB-->>L: 📋 Employee Found (is_active = false)
            L-->>AG: ⚠️ 409 Conflict
            AG-->>C: ❌ 409 Conflict
        else ✅ Employee Active
            DB-->>-L: 📋 Employee Data (is_active = true)
            
            L->>L: 🛡️ Prepare Soft Delete
            L->>+DB: 💾 Update Employee Record
            
            alt ❌ Update Failed
                DB-->>L: 💥 Update Error
                L-->>AG: 🚫 500 Internal Server Error
                AG-->>C: ❌ 500 Internal Server Error
            else ✅ Delete Success
                DB-->>-L: ✅ Update Confirmation
                L->>L: 📝 Log Deletion Event
                L-->>-AG: ✅ 204 No Content
                AG-->>-C: 🎉 204 No Content
            end
        end
    end

🗑️ Delete Employee Process

🛡️ Soft Delete Strategy

Preserves employee data by setting is_active=false instead of physical deletion for data integrity

📝 Audit Trail

Maintains complete audit history with deleted_at timestamp for compliance and regulatory requirements

💾 Data Preservation

Employee data remains in database for future reference and reporting with complete history preservation
